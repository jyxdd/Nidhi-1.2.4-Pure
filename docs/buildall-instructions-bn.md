# কার্নেল বিল্ড TUI ড্রাইভার

কার্নেল বিল্ড স্ক্রিপ্টের জন্য একটি ব্যবহারকারী-বান্ধব ncurses-ভিত্তিক ইন্টারফেস।

**লেখক:** kaixenber  
**সংস্করণ:** 1.0

## বৈশিষ্ট্যসমূহ

### গ্রাফিক্যাল ইন্টারফেস
- `dialog` ব্যবহার করে Ncurses TUI
- অ্যারো কী এর মাধ্যমে সহজ নেভিগেশন
- পরিষ্কার ভিজ্যুয়াল ফিডব্যাক
- অগ্রগতি ট্র্যাকিং

### মাল্টি-ডিভাইস সাপোর্ট
- একসাথে একাধিক ডিভাইস নির্বাচন
- একটি কমান্ড দিয়ে অনুক্রমিক বিল্ড
- বন্ধুত্বপূর্ণ নাম সহ পূর্বনির্ধারিত ডিভাইস তালিকা
- সমস্ত উপলব্ধ defconfigs দেখানোর অপশন

### সম্পূর্ণ বিল্ড কন্ট্রোল
- KernelSU সক্রিয়/নিষ্ক্রিয় টগল

- লিনাক্স অপারেটিং সিস্টেম (Ubuntu/Debian সুপারিশকৃত)
- `dialog` প্যাকেজ (অনুপস্থিত থাকলে স্বয়ংক্রিয়ভাবে ইনস্টল হয়)
- `build.sh` স্ক্রিপ্টটি একই ডিরেক্টরিতে থাকতে হবে

### কার্নেল সোর্স
- অবশ্যই কার্নেল রুট ডিরেক্টরি থেকে চালাতে হবে
- `arch/arm64/configs/` ডিরেক্টরি বিদ্যমান থাকতে হবে
- ডিভাইসের defconfig ফাইলগুলি উপস্থিত থাকতে হবে

## ইনস্টলেশন

### ১. স্ক্রিপ্ট ডাউনলোড
আপনার কার্নেল সোর্স রুট ডিরেক্টরিতে `build_tui.sh` রাখুন।

```bash
cd /path/to/kernel/source
# Copy build_tui.sh here
```

### ২. এক্সিকিউটেবল তৈরি করা
নিশ্চিত করুন যে স্ক্রিপ্টটির এক্সিকিউশন পারমিশন আছে।

```bash
chmod +x build_tui.sh
```

### ৩. build.sh যাচাই করুন
নিশ্চিত করুন যে `build.sh` একই ডিরেক্টরিতে উপস্থিত আছে।

```bash
ls -l build.sh build_tui.sh
```

## ব্যবহার

### TUI শুরু করা
টার্মিনাল থেকে স্ক্রিপ্টটি চালান:

```bash
./build_tui.sh
```

### নেভিগেশন নিয়ম
- **অ্যারো কী**: মেনুতে উপরে/নিচে নেভিগেট করতে
- **SPACE**: চেকলিস্টে আইটেম নির্বাচন/অনির্বাচন করতে
- **ENTER**: নির্বাচন নিশ্চিত করতে
- **ESC**: বাতিল বা পূর্ববর্তী মেনুতে ফিরে যেতে
- **TAB**: বোতামগুলির মধ্যে ফোকাস পরিবর্তন করতে

## বিল্ড প্রক্রিয়ার ওভারভিউ

### ধাপ ১: ডিভাইস নির্বাচন
স্পেস বার ব্যবহার করে তালিকা থেকে এক বা একাধিক ডিভাইস নির্বাচন করুন। নিশ্চিত করতে ENTER টিপুন।

### ধাপ ২: KernelSU নির্বাচন
KernelSU সহ SUSFS সাপোর্ট সক্রিয় করবেন কিনা তা চয়ন করুন।

### ধাপ ৩: রম টাইপ নির্বাচন
টার্গেট রমের ধরন নির্বাচন করুন:
- **Both AOSP and MIUI**: প্রতি ডিভাইসে দুটি জিপ ফাইল তৈরি করে।
- **AOSP only**: প্রতি ডিভাইসে একটি জিপ ফাইল তৈরি করে।
- **MIUI only**: প্রতি ডিভাইসে একটি জিপ ফাইল তৈরি করে।

### ধাপ ৪: বিল্ড অপশন
অতিরিক্ত বিল্ড প্যারামিটার কনফিগার করুন:
- **Verbose mode (-V)**: বিস্তারিত আউটপুট সক্ষম করে।
- **Dirty build (-D)**: আউটপুট ডিরেক্টরি পরিষ্কার করা এড়িয়ে যায়।
- **Custom job count**: প্যারালাল জবের সংখ্যা নির্দিষ্ট করার অনুমতি দেয়।

### ধাপ ৫: বিল্ড সারাংশ
নির্বাচিত কনফিগারেশন পর্যালোচনা করুন। বিল্ড প্রক্রিয়া এগিয়ে নিতে নিশ্চিত করুন।

### ধাপ ৬: বিল্ড এক্সিকিউশন
স্ক্রিপ্টটি প্রতিটি নির্বাচিত ডিভাইসের জন্য পর্যায়ক্রমে বিল্ড চালাবে। পর্যবেক্ষণের জন্য সম্পূর্ণ বিল্ড আউটপুট প্রদর্শিত হয়।

### ধাপ ৭: সমাপ্তি
সমাপ্তির পরে, সফল এবং ব্যর্থ বিল্ডগুলির একটি সারাংশ প্রদর্শিত হয়। বিল্ড লগগুলি `build_*.log` হিসেবে এবং ফ্ল্যাশযোগ্য জিপ ফাইলগুলি `out/` ডিরেক্টরিতে সংরক্ষিত হয়।

## সেটিংস মেনু

### সমস্ত Defconfigs দেখান
**OFF (ডিফল্ট):**
শুধুমাত্র পরিচিত ডিভাইসগুলির কিউরেটেড তালিকা প্রদর্শন করে।

**ON:**
`arch/arm64/configs/`-এ পাওয়া সমস্ত উপলব্ধ defconfigs প্রদর্শন করে, স্টক defconfigs বাদ দিয়ে। এটি পূর্বনির্ধারিত তালিকায় নেই এমন ডিভাইসগুলির জন্য বিল্ড করার জন্য দরকারী।

### সম্পর্কে (About) সেকশন
সংস্করণ এবং লেখকের তথ্য প্রদর্শন করে।

## উদাহরণ

### উদাহরণ ১: একক ডিভাইস, সাধারণ বিল্ড
1. TUI লঞ্চ করুন: `./build_tui.sh`
2. "Start Build Process" নির্বাচন করুন
3. ডিভাইস নির্বাচন করুন: `[X] lmi`
4. KernelSU: `No`
5. রম টাইপ: `Both AOSP and MIUI`
6. বিল্ড অপশন: (কিছুই নির্বাচিত নেই)
7. নিশ্চিত করুন এবং বিল্ড করুন

**ফলাফল:** KernelSU ছাড়াই lmi-এর জন্য AOSP এবং MIUI জিপ তৈরি করে।

### উদাহরণ ২: KernelSU সহ একাধিক ডিভাইস
1. TUI লঞ্চ করুন
2. ডিভাইস নির্বাচন করুন: `umi`, `lmi`, `alioth`
3. KernelSU: `Yes`
4. রম টাইপ: `Both`
5. বিল্ড অপশন: `Verbose mode`, `Custom job count: 8`
6. নিশ্চিত করুন এবং বিল্ড করুন

**ফলাফল:** ৮টি প্যারালাল জব ব্যবহার করে, ভার্বোস আউটপুট সহ, KernelSU সহ তিনটি ডিভাইসের জন্যই জিপ তৈরি করে।

## ফিচারের বিস্তারিত

### মাল্টি-ডিভাইস নির্বাচন
একই কনফিগারেশন সহ একাধিক ডিভাইসের অনুক্রমিক বিল্ড করার অনুমতি দেয়। যদি কোনো ডিভাইসের বিল্ড ব্যর্থ হয়, স্ক্রিপ্টটি পরবর্তী ডিভাইসে চলে যায়।

### পূর্বনির্ধারিত ডিভাইস তালিকা
শনাক্তকরণ ত্রুটি এড়াতে ব্যবহারকারী-বান্ধব নাম সহ সমর্থিত এবং পরীক্ষিত ডিভাইসগুলির একটি কিউরেটেড তালিকা প্রদান করে।

### ডায়নামিক Defconfig ডিসকভারি
উপলব্ধ ডিভাইস কনফিগারেশন তালিকাভুক্ত করতে `arch/arm64/configs/` স্ক্যান করে, স্টক defconfigs বাদ দিয়ে।

### বিল্ড সারাংশ
সঠিকতা নিশ্চিত করতে এক্সিকিউশনের আগে সমস্ত নির্বাচিত অপশনের একটি বিস্তৃত সারাংশ প্রদর্শন করে।

## টিপস এবং সেরা অভ্যাস

### দ্রুত একক বিল্ড
`./build_tui.sh` চালান, একটি একক ডিভাইস নির্বাচন করুন, ডিফল্ট অপশন গ্রহণ করুন এবং নিশ্চিত করুন।

### ব্যাচ বিল্ডিং
সমস্ত টার্গেট ডিভাইস নির্বাচন করুন, KernelSU এবং রম টাইপ কনফিগার করুন এবং দ্রুত পুনরাবৃত্তির জন্য ঐচ্ছিকরূপে ডার্টি বিল্ড সক্ষম করুন।

### ডেভেলপমেন্ট ওয়ার্কফ্লো
ইটারেটিভ ডেভেলপমেন্টের জন্য, যদি নন-স্ট্যান্ডার্ড ডিভাইস ব্যবহার করেন তবে "Show all defconfigs" সক্ষম করুন এবং কম্পাইলেশন দ্রুত করতে "Dirty build" অপশন ব্যবহার করুন।

## ট্রাবলশুটিং

### ডায়লগ ইনস্টল করা নেই
**ত্রুটি:** `dialog: command not found`

**সমাধান:**
স্ক্রিপ্টটি `dialog` স্বয়ংক্রিয়ভাবে ইনস্টল করার চেষ্টা করে। যদি এটি ব্যর্থ হয়, তবে এটি ম্যানুয়ালি ইনস্টল করুন:
```bash
sudo apt-get update && sudo apt-get install dialog
```

### বিল্ড স্ক্রিপ্ট পাওয়া যায়নি
**ত্রুটি:** `Build script not found at: ./build.sh`

**সমাধান:**
নিশ্চিত করুন `build.sh` টি `build_tui.sh`-এর মতোই একই ডিরেক্টরিতে অবস্থিত।

### কোনো Defconfigs পাওয়া যায়নি
**ত্রুটি:** `No defconfigs found`

**সমাধান:**
নিশ্চিত করুন যে স্ক্রিপ্টটি কার্নেল সোর্স ডিরেক্টরিটির রুট থেকে চালানো হচ্ছে।

### ডিভাইস তালিকায় নেই
**সমস্যা:** টার্গেট ডিভাইস তালিকায় দৃশ্যমান নয়।

**সমাধান:**
সেটিংস মেনুতে "Show all defconfigs" সক্ষম করুন, অথবা স্ক্রিপ্টে `KNOWN_DEVICES` অ্যারেতে ম্যানুয়ালি ডিভাইসটি যোগ করুন।

## অ্যাডভান্সড ব্যবহার

### ডিভাইস তালিকা পরিবর্তন করা
যাচাইকৃত তালিকায় একটি নতুন ডিভাইস যোগ করতে, `build_tui.sh`-এ `KNOWN_DEVICES` অ্যারে এডিট করুন:

```bash
declare -A KNOWN_DEVICES=(
    ...
    ["surya"]="POCO X3 / Redmi Note 9 Pro"
    ...
)
```

### অটোমেশন
যদিও `build_tui.sh` ইন্টারেক্টিভ ব্যবহারের জন্য ডিজাইন করা হয়েছে, তবে অন্তর্নিহিত `build.sh` অটোমেশন এবং CI/CD পাইপলাইনের জন্য ব্যবহার করা যেতে পারে।

## ফাইল স্ট্রাকচার

```
kernel-source/
├── build.sh              # মেইন বিল্ড স্ক্রিপ্ট
├── build_tui.sh          # TUI ড্রাইভার স্ক্রিপ্ট
├── arch/arm64/configs/   # ডিভাইস defconfigs
├── anykernel/            # AnyKernel3 ডিরেক্টরি
├── out/                  # বিল্ড আউটপুট ডিরেক্টরি
└── build_*.log           # বিল্ড লগ
```

## প্রায়শই জিজ্ঞাসিত প্রশ্ন (FAQ)

**প্রশ্ন: আমি কি তালিকায় নেই এমন ডিভাইসের জন্য বিল্ড করতে পারি?**
উত্তর: হ্যাঁ, সেটিংস মেনুতে "Show all defconfigs" সক্ষম করুন।

**প্রশ্ন: আমি কি কোনো ডিভাইস নির্বাচন না করতে পারি?**
উত্তর: না, অন্তত একটি ডিভাইস নির্বাচন করতে হবে।

**প্রশ্ন: যদি কোনো বিল্ড ব্যর্থ হয় তবে কী হবে?**
উত্তর: স্ক্রিপ্টটি বাকি নির্বাচিত ডিভাইসগুলির বিল্ড চালিয়ে যাবে এবং শেষে ব্যর্থতা রিপোর্ট করবে।

**প্রশ্ন: আমি কি বিল্ড প্রক্রিয়া বাতিল করতে পারি?**
উত্তর: হ্যাঁ, বাতিল করতে `Ctrl+C` টিপুন। যেকোনো সম্পন্ন বিল্ড `out/` ডিরেক্টরিতে থাকবে।
